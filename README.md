# 北科無人機社 官方網站暨動態管理系統 (NTUT Drone Club Website & CMS)

這是一個專為**國立臺北科技大學無人機社 (NTUT Drone Club)** 量身打造的官方網站與動態內容管理系統（CMS）。系統採用現代感的 **FPV 穿越機科技風**與**極客暗色美學**設計，並建構於高穩定、低延遲的 **Cloudflare Workers + KV** 無伺服器架構之上。

本專案特別結合了 **GitHub Actions 自動化部署 (CI/CD)** 與 **GitHub API 媒體庫整合**，讓您可以**完全在雲端進行網站的管理與發佈，無須在本地電腦執行任何部署指令**！

---

## 🌟 核心特色與架構優勢

1. **🚀 100% 雲端自動化部署 (Zero-Local Deployment)**
   * 結合 **GitHub Actions**，只要將程式碼推送到 GitHub 儲存庫（或在網頁端修改與審核），系統即會自動將安全金鑰動態注入並部署至 Cloudflare Workers，無須在本地端繁瑣安裝或執行 Wrangler 指令。
2. **🌐 雙語語系動態切換 (i18n Support)**
   * 前台頂端導覽列支援「中文 / English」即時切換，並以 Cookie 記憶使用者語言偏好。
   * 後台發佈文章與頁面時，皆可指定專屬語系，實現真正的多語系國際化動態網站。
3. **🖼️ 文章圖片**
   * 文章與頁面可用 Markdown 引用 `https://` 圖片網址（例如社群或雲端相簿的公開連結）。基於安全考量，後台不提供直接上傳檔案到網站的功能。
4. **📝 動態頁面與文章管理 (CMS Dashboard)**
   * **動態部落格**：支援 Markdown 完整語法，編輯時可即時預覽。
   * **獨立頁面生成器**：免改程式碼！可在後台任意建立如 `/page/info`、`/page/join` 等專屬客製化網頁。
5. **✨ 極客風炫酷主視覺**
   * **Telemetry 動態背景**：以 Canvas 繪製遙測格線與互動式連線粒子效果。
   * **3D 互動飛機浮動**：Hero 區塊的無人機視覺圖隨滑鼠移動進行 3D 姿態偏轉。

## 🚀 完整部署教學 (完全免本地指令流程)

本網站已經為您設定好自動化部署管線（CI/CD），您只需要完成以下簡單的雲端設定，即可啟用一鍵發佈功能！

### 第一步：在 Cloudflare 準備所需資源
1. 登入 [Cloudflare 控制台](https://dash.cloudflare.com/)。
2. **建立 KV 資料庫**：
   * 前往 **Workers & Pages** -> **KV** -> 點擊 **Create Namespace**。
   * 命名為 **`DRONE_DB`**，點擊 Add 建立。
   * 建立成功後，複製此 KV 的 **ID**（一串英數字元，例如 `abc123e456...`）。
3. **取得 Cloudflare Account ID**：
   * 在 Cloudflare 控制台右下角（或網址列中）找到並複製您的 **Account ID**。
4. **建立 API Token (用於部署授權)**：
   * 點擊右上角個人頭像 -> **My Profile** -> **API Tokens** -> **Create Token**。
   * 選擇 **Edit Cloudflare Workers** 模板（或自訂權限包含 `Workers KV Storage:Edit`, `Workers Routes:Edit`, `Workers Scripts:Edit`）。
   * 建立後，複製並妥善保存這組 **API Token**。

### 第二步：在 GitHub 儲存庫設定環境金鑰 (Repository Secrets)
為了安全起見，我們不把敏感的 ID 與金鑰直接寫入程式碼，而是設定在 GitHub 的安全機密庫中，由 GitHub Actions 自動注入：
1. 進入您的 GitHub 儲存庫 (`jhuiry8/ntutdroneweb`) -> 點擊上方 **Settings (設定)**。
2. 左側選單展開 **Secrets and variables** -> 點擊 **Actions**。
3. 在 **Repository secrets** 區塊，點擊 **New repository secret**，依序新增以下 3 個安全機密變數：

| Secret 名稱 | 填入的內容 | 作用說明 |
| :--- | :--- | :--- |
| **`CLOUDFLARE_ACCOUNT_ID`** | 您在第一步取得的 Cloudflare 帳戶 ID | 授權 Wrangler 部署到您的帳號 |
| **`CLOUDFLARE_API_TOKEN`** | 您在第一步建立的 Cloudflare API Token | 執行自動部署的權限憑證 |
| **`CLOUDFLARE_KV_ID`** | 您在第一步建立的 `DRONE_DB` KV Namespace ID | **安全注入**到 KV 資料庫綁定中 |

> 🎉 **自動化驗證與發佈**：設定完成這 3 個 Secrets 後，只要您在專案有任何 Push 行為（或在 Actions 頁面手動觸發），系統便會開始執行 `.github/workflows/deploy.yml`，自動完成打包、金鑰注入與 Cloudflare Workers 發佈！您可以隨時到 GitHub **Actions** 分頁查看綠色的成功打勾圖示。

## 💻 網站使用與後台操作指南

部署成功後， Cloudflare 會給予您一個專屬網址（例如 `https://ntut-drone-web.您的帳號.workers.dev`，也可以在 Cloudflare 後台綁定自訂網域）。

### 1. 後台登入、帳號與權限
* **後台登入網址**：`https://您的網站網址/admin`
* 新部署時，先在 Cloudflare Worker 的加密環境變數設定 `ADMIN_INITIAL_PASSWORD`（至少 8 位）。首次以 `admin` 與此密碼登入後，系統會建立社長帳號；請立即移除該環境變數。
* 既有部署若 KV 中已有 `admin_password_hash`，可用原管理密碼登入 `admin`；首次成功登入會轉換成新的逐帳號密碼格式。
* 社長可在「帳號與權限」新增帳號、設定角色、停用帳號及重設密碼。角色為社長、財務、一般幹部、社員。社長與一般幹部可編輯 CMS；財務可查看 CMS；社員可登入並修改自己的密碼，後續社員資料功能將整合於此帳號。
* 帳號密碼至少 8 位。修改或重設密碼會使舊 session 失效。登入密碼連續錯誤 5 次會暫停 15 分鐘（依帳號與來源 IP 計）。
* 密碼使用 PBKDF2-SHA256、隨機 salt 與 100,000 次迭代，格式中記錄迭代次數，以符合正式 Cloudflare Workers 上限。舊站 `admin_password_hash` 仍可自動轉換；若曾在其他執行環境建立 120,000 次的 `pbkdf2:salt:hash` 帳號，需由可登入的社長重設該帳號密碼，不會自動覆寫既有憑證。若唯一管理員也使用該格式，需由部署管理者進行帳號復原。
* 若要啟用登入驗證碼，請在 Cloudflare Turnstile 建立對應網站網域的 widget，將公開 site key 設為 Worker 變數 `TURNSTILE_SITE_KEY`，secret key 設為 Worker 加密變數 `TURNSTILE_SECRET_KEY`。兩者設定後，登入表單會顯示驗證碼，伺服器會透過 Siteverify 驗證每次登入。未設定 Turnstile 時，登入頁會自動改用內建的圖形驗證碼（5 個字元、不分大小寫、5 分鐘內有效且只能使用一次，可按「換一張」更新），不需額外設定。另外同一帳號＋IP 連續失敗 5 次、或同一 IP 失敗 20 次（含驗證碼錯誤）都會鎖定 15 分鐘，防止暴力破解。驗證碼與失敗次數存放在 Durable Object（`SITE_STORE`，部署時由 `wrangler.toml` 的 migration 自動建立），同時送出大量請求也無法重複使用同一張驗證碼或超過次數上限；文章與頁面列表的更新也經由它排隊，多位幹部同時存檔不會互相覆蓋。

#### 舊網站轉換步驟
1. 舊網站只有共用管理密碼，沒有個別使用者資料，因此不會自動產生每位管理者的帳號。部署新版後，原管理者在 `/admin` 輸入帳號 `admin` 與原本的共用密碼；若啟用了 Turnstile，先完成驗證碼。
2. 第一次登入會把舊 KV 的 `admin_password_hash` 轉成新的 `admin` 社長帳號，原文章、頁面與首頁設定仍沿用原 KV 資料，不需重新匯入。舊 session 在轉換後失效，其他人需重新登入。
3. `admin` 到「系統設定」更換密碼，再到「帳號與權限」為每位社長、財務、幹部或社員建立個別帳號並提供初始密碼。每人登入後應更換自己的密碼。不要再共用 `admin` 帳號。
4. 若舊 KV 尚未建立 `admin_password_hash`（例如舊站從未有人登入），需先設定 `ADMIN_INITIAL_PASSWORD`，用 `admin` 與該密碼首次登入，完成後移除該變數。

### 1-1. 手機版行動支援（PWA 純網頁加入主畫面 & 原生 Android APK）
* **🍎 蘋果 iOS (iPhone / iPad)**：支援 **PWA 純網頁加入主畫面**。使用 Safari 開啟社團網站後，點擊下方「分享」圖示 ➔ 「加入主畫面」，即可像原生 App 一樣以獨立全螢幕開啟，自動隱藏網址列，享有 iPhone Safari 安全邊界適配（動態島／瀏海／底部 Home Bar）、Service Worker 離線快取與智慧安裝導引。
* **🤖 安卓 Android**：
  * **純網頁 PWA 一鍵安裝**：以 Chrome 開啟網站時點擊「安裝應用程式」或「新增至主畫面」即可安裝至桌面。
  * **100% 原生 Material Design APK 安裝包**：專案目錄 `android/` 提供**全原生 Android 專案**（**徹底拋棄 WebView 瀏覽器包殼做法**），採用 Material Components 原生 UI 架構：
    * 底部原生導覽列 (`BottomNavigationView`) 整合首頁動態、最新公告、設備借用、會議簽到與個人社員中心。
    * 支援原生 `RecyclerView` 卡片清單、`SwipeRefreshLayout` 手勢下拉更新、原生借用與會議簽到對話框。
    * 原生非同步網路層直接對接後端 RESTful API (`/api/*`)，自動管理 Session Cookie 與本機安全儲存。
    * 透過 GitHub Actions（`.github/workflows/android.yml`）每次推送皆會自動編譯 APK，社員與幹部可直接在 GitHub Releases / Actions 下載安裝。


### 2. 文章管理 (Blog Posts)
* 文章與頁面保留 Markdown 格式、表格、圖片及基本文字格式；腳本、事件屬性、危險連結與 iframe 等主動內容會在顯示時移除，既有內容亦適用。後台預覽使用相同的伺服器過濾規則，需要連線；預覽無法載入時會顯示純文字。
* 在 **「文章管理」** 分頁點擊「新增文章」。

### 3. 社務管理
* 後台導覽分為「網站管理」、「社務管理」與「系統管理」：文章、頁面、媒體庫與首頁設定放在網站管理；表單申請、社員、財務、設備及社課備忘錄放在社務管理；系統設定與帳號權限集中於系統管理。
* 社長與財務帳號可使用「財務管理」與「社員管理」；一般幹部也可管理設備列管。社員帳號不能存取這些管理模組，但可使用表單申請、法規查詢及查看自己綁定的社員資料。
* 財務可新增收入、支出或現金與郵局間的轉帳。每筆帳目先標為「待審核」；只有社長可以核准或退回。僅已核准帳目會計入現金、郵局與總餘額。
* 既有帳本可從 Google 試算表或 Excel 下載成 CSV，再於「匯入既有帳本」選擇檔案；也可直接貼上表格。欄位標題需為：`日期`、`事宜`、`收入`、`支出`、`現金餘額`、`郵局餘額`；`總計` 可存在但會忽略。日期可為 `2026/5/14` 或 `2026-05-14`。系統依每列的現金與郵局餘額差額辨識收入、支出及帳戶間轉帳。
* 預算分類可以手動建立或匯入兩欄 CSV／TSV：`分類,預算`。核准的支出可歸入分類，系統會顯示已用與剩餘預算。
* 「社員管理」可依姓名、學號、Email、電話、幹部職務、備註或綁定帳號查詢，並能新增、編輯或刪除社員資料。姓名和學號至少填一項，因此可先用學號建立待核對資料；也能補上幹部職務與備註。社員名冊不會自動建立網站登入帳號。
* **社員身分與社費狀態**依《社員與幹部四級分級細則》與《無人機社社費細則》（115.09.01 修訂），並與 Django 社團管理系統（`droneclubmangsystem` 的 `User.membership_status`／`fee_status`）使用相同分類：
  * 身分：非正式社員（`TRIAL`）、正式社員（`MEMBER`）、籌備幹部（`PREP_OFFICER`）、正式幹部（`OFFICER`）。非正式社員可記錄本學年已用的免費體驗社課次數（上限 2 次）。
  * 社費：未繳費（`UNPAID`）、學期會籍 500 元（`SEMESTER_PAID`，只在繳費學期有效，例如 `115-1`；8 月至 1 月為第 1 學期、2 月至 7 月為第 2 學期）、在學會籍 1,000 元（`LIFETIME_PAID`）。
  * 新增社員預設為「未繳費的正式社員」，可先登記再收費；列表可篩選「未繳費社員」、「具表決權（社員總額）」、各級身分或「未綁定帳號」，頁首顯示名冊人數、社員總額、未繳費人數與非正式社員人數。
  * 表決權：正式幹部在任期間具表決權；正式社員與籌備幹部須已繳當學期會籍或具在學會籍；未繳費的籌備幹部與正式幹部顯示「幹部免繳」，但未繳費籌備幹部不具表決權；非正式社員無表決權。
  * CSV 匯入可加「身分」、「社費狀態」欄，值可填中文（如「未繳費」、「學期會籍」）或 Django 代碼（如 `UNPAID`、`PREP_OFFICER`）。從社費帳本匯入時，收入 1,000 元以上視為在學會籍、500 元以上視為該日期學期的學期會籍。
* 「社費簽收」可選擇已造冊社員或手動填寫繳費者，記錄金額、繳費方案、日期、收款人姓名與收據編號／線索，便於比對不完整的收據資料。選擇已造冊社員（或填寫名冊中已有的學號）時，系統依方案（未選時 500 元視為學期會籍、1,000 元視為在學會籍）把該社員更新為已繳費，非正式社員同時轉為正式社員；在學會籍不會被之後的學期繳費降級。刪除簽收紀錄不會改回社費狀態。簽收歷史可查閱或刪除；此記錄獨立於財務帳目，不會自動建立或核准帳目。
* **帳號與社員綁定**：社長在「帳號與權限」新增帳號時可直接選擇社員，或在帳號列表用「儲存綁定」綁定／解除。一位社員只能綁定一個帳號；刪除社員會自動解除綁定；只變更綁定不會讓對方登出。綁定後，任何角色的帳號都能在「系統設定 → 我的社員資料」查看自己的身分、社費、表決權與繳費紀錄（不含幹部備註）。
* **法規查詢**：所有登入帳號都可在「社務管理 → 法規查詢」閱讀本社組織章程、四級分級細則、社費細則、社課守則（115.09.01 修訂）及學校《學生社團組織及活動實施辦法》，輸入關鍵字或點常用關鍵字會列出符合的條文並標示關鍵字。尚未有修正生效前使用 `src/regulations.js` 內建的條文。
* **法規不能直接修改**，只能透過「修正案」依規定程序變更（規則在 `src/regulation-rules.js`）：
  * 幹部（社長、財務、一般幹部）可代為登錄修正、制定或廢止的提案，必須填修正理由；提案期間條文不變，所有帳號都看得到提案與條文差異。
  * **組織章程**（章程第十條第四款、第十三條）：提案來源須為法規監察委員會，或正式社員 5 人以上連署；社長登錄社員大會結果時，系統檢查「社員總額三分之二以上出席、出席社員三分之二以上同意」，未達門檻不能登錄通過；通過後狀態為「待學校核備」，登錄學校核備日期後才生效。章程不能廢止。
  * **施行細則**：須登錄幹部會議通過日期與社長核定日期；涉及社員權利義務之重大變更或社費標準時，提案勾選「需社員大會」，另須登錄社員大會結果（一般決議：社員總額三分之一以上出席、出席社員二分之一以上同意）。
  * **學校法規**：本社不能修改，只能在學校公告新版後，登錄公告日期與來源並更新為學校版本。
  * 會議未通過時由社長登錄「未通過」並說明情形；提案人或社長可撤回。若同一法規已有其他修正先生效，舊提案會被拒絕，需以最新條文重新提案。生效後保留修正沿革（最近 20 版），可比較各版差異。提案與沿革存於 KV `club:regulation-amendments`、`club:regulations`。
* **全選與批次修改**：社員列表每列有勾選框，「全選」會選取目前列表（可先用篩選，例如「未繳費社員」）。選好後可一次把身分或社費狀態改成指定值（學期會籍可填學期，留空為本學期），或一次刪除；送出前會確認人數。任何一筆資料不合格時整批都不會修改。舊名冊升級後全部顯示為「未繳費正式社員」，可用此功能快速校正。
* 社員管理的便利功能：未繳費社員列上有「記錄繳費」可直接帶入社費簽收（選方案自動填金額、記住上次的收款人）；社長可在未綁定的社員列按「建立帳號」，帳號預設為學號並自動選好綁定對象；編輯社員時會顯示「正在編輯：某某」；刪除社員或停用帳號前會提示影響。
* 「設備管理」可建立與編輯列管設備，記錄財產編號、分類、原廠序號、購入資訊、狀況、存放位置、保管人及備註。財產編號由系統產生，原廠序號不可重複；退役設備標記為「已除列」以保留紀錄。可勾選多件設備，列印含社團名稱、設備名稱、分類及財產編號的標籤。
* 「社課備忘錄」可集中記錄社課日期、課程名稱、課程重點、作業提醒與多個教材或會議網址。社長與一般幹部可新增、刪除；可查看 CMS 的角色能瀏覽紀錄。資料保存在 Cloudflare KV，不會公開在網站前台。
* 輸入**文章標題**與**網址代稱 (Slug)**（例如 `welcome-to-drone-club`，將對應至 `/blog/welcome-to-drone-club`）。
* 選擇**語言類別**（`zh` 為中文，`en` 為英文）。
* 在內容編輯器中使用 Markdown 語法撰寫，可利用右側預覽視窗即時確認效果。

### 3-1. 表單申請（紙本簽核）
* 後台「社務管理 → 表單申請」開放所有登入帳號（含社員）使用：線上填寫、儲存後開啟 A4 列印頁，**審核與簽名一律以紙本為準**，網站不做線上核准。
* 支援六種表單，版面依社團與學校現行紙本表單製作：
  * **社費支出事前申請單**、**社費事後報銷單**（財務管理表單第一聯／第二聯）：自動計算小計、總額與新台幣大寫金額；報銷單可「從事前申請單帶入」品項，再改成實際金額，並保留憑證黏貼區。
  * **設備借據**：一張 A4 印出「第一聯 社團存查」與「第二聯 借用人收執」，可從設備管理清單直接加入設備與財產編號，自動計算借用天數。
  * **學生活動申請表**、**學生活動報告表**：依課指組 113.1.16 版格式，含品德教育、永續發展勾選；報告表可「從活動申請表帶入」名稱、時間、地點與勾選項目。
  * **公文（函／簽／公告）**：可輸入白話內容，由 AI 轉成主旨與說明，產生後請自行確認再儲存。
* **AI 協助填寫**：每種表單上方都有「AI 幫我填」，用一段話描述需求（例如「張同學下週五早上 9 點借 Mini 4 Pro 到週日，成果展空拍」），AI 會填入對應欄位、換算日期，並提示還缺哪些資料；借據會自動對應設備清單的財產編號。AI 回傳的內容會在伺服器端逐欄檢查，不合格式或不存在的欄位一律捨棄，填完仍須自行檢查再儲存。
* 自動填寫：填表人姓名、學號、系級、職稱、電話會記在該裝置，下次自動帶入；社長與財務可從社員名冊帶入，幹部可從設備清單加入設備。
* 表單依類型與民國年自動編號（例如 `申115-001`、`借115-003`），編號只增不減，刪除表單後也不會重複使用。表單、編號與每日次數限制都存放在 Durable Object（`FORM_STORE`，部署時由 `wrangler.toml` 的 migration 自動建立），多人同時送出也不會互相覆蓋。社員只看得到自己的表單；社長、財務、一般幹部可查看全部。只有填表人或社長可以修改、刪除。每種表單也能「列印空白表單」手寫使用。
* **公開的設備借用申請**：網址 `/forms/equipment-loan`（前台頁尾「設備借用申請」也有連結），**不需登入**即可填寫設備借據，學號與電話須自行填寫且為必填；此頁**不提供 AI 功能**。送出後會取得借據編號與列印連結（3 天內有效、僅填寫者持有）；借用日期不可早於當天、線上借用期間最長 30 天，填寫日期由伺服器自動帶入，請對方列印、簽名後交給財產管理人與社長簽核。
  * 送出的借據會存入後台「表單紀錄」並標示「外部填寫」，社長、財務、一般幹部可查看、補填財產編號或刪除；社員帳號看不到外部借據。
  * 防濫用：同一 IP 每日最多送出 5 張、全站每日最多 200 張，外部借據另有 1,000 筆的獨立上限，不會佔用幹部的表單額度；送出前須通過驗證碼：已設定 Turnstile（`TURNSTILE_SITE_KEY`／`TURNSTILE_SECRET_KEY`）時使用 Turnstile，否則使用與登入頁相同的內建圖形驗證碼。
* 社長可在「表單設定」修改列印抬頭、社團簡稱、社長姓名（借據與公文署名）、財產管理人與指導老師。
* 啟用 AI：在 Cloudflare Worker 新增加密變數 **`GROQ_API_KEY`**（[Groq Console](https://console.groq.com/keys) 建立的金鑰）；可選填一般變數 `GROQ_MODEL`（預設 `openai/gpt-oss-120b`，想更快可改 `openai/gpt-oss-20b`）。若未設定 Groq 但有 `GEMINI_API_KEY`，會改用 Google Gemini（`GEMINI_MODEL` 預設 `gemini-2.5-flash`）。後台「表單申請」標題下方會顯示目前使用的 AI。
* AI 填寫表單開放所有登入帳號；AI 公文僅社長、財務、一般幹部可用。與下方「AI 助理與自動化」共用每人每日上限（預設 30 次）。未設定金鑰時，其他表單功能照常可用。
* 列印時請選 A4、縮放 100%，並取消瀏覽器的「頁首及頁尾」；也可在列印對話框選「另存為 PDF」。

### 3-2. AI 助理與自動化
啟用方式與表單 AI 相同（設定 `GROQ_API_KEY` 或 `GEMINI_API_KEY`）。所有 AI 結果都只是**建議**：AI 不能直接修改任何資料，必須由使用者檢查、按下確認才會寫入。

| 功能 | 位置 | 可使用的角色 |
| :--- | :--- | :--- |
| **AI 助理**：用聊天方式查社費、設備、帳目、表單、會議、法規條文，並可建議「開啟文章草稿」「送出待審核帳目」等動作 | 側邊欄「AI 工具 → AI 助理與週報」或右下角 AI 按鈕 | 所有帳號（只能查到自己權限內的資料；社員只能查法規、修正案與自己的表單） |
| **AI 寫作助手**：依重點產生文章草稿、潤稿、產生摘要與網址代稱、翻成另一語言另存新文章 | 文章／頁面編輯器上方 | 社長、一般幹部 |
| **AI 帳目檢查**：找出可能重複、送審超過 14 天或可疑的帳目，並為未分類支出建議預算分類（勾選後套用） | 財務管理 | 社長、財務 |
| **AI 整理雜亂名單**：把格式混亂的名單整理成社員匯入預覽（每次最多約 150 人） | 社員管理 → 大量新增 | 社長、財務 |
| **AI 審閱修正案**：比對修正前後條文，對照組織章程與學校辦法，指出可能牴觸、用語不一致之處；同時列出系統判定的通過程序 | 法規查詢 → 修正案、提出修正案表單 | 社長、財務、一般幹部 |
| **每週社務報告**：每週一 09:00（臺灣時間）自動統計財務、社員、設備借用、表單與修正案，由 AI 寫成摘要 | AI 助理與週報 | 檢視：幹部（一般幹部看不到財務、社員、設備數字）；手動產生：社長、財務 |

* **選填設定**（Cloudflare Worker 變數）：
  * `AI_DAILY_LIMIT`：每人每日 AI 使用次數上限（1–1000，預設 30）。AI 助理每問一題算 1 次。
  * `REPORT_WEBHOOK_URL`（建議設為加密變數）：Discord 或 Slack 的 Incoming Webhook 網址，設定後週報會自動發送到社團群組。
  * 排程設定在 `wrangler.toml` 的 `[triggers] crons`（預設 `0 1 * * 1`，即每週一 UTC 01:00）。未設定 AI 金鑰時，週報仍會產生系統統計，只是沒有 AI 摘要。
* **個資提醒**：AI 助理查社員資料時不會取得電話與 Email；「AI 整理雜亂名單」則會把貼上的名單送到 AI 服務商（Groq 或 Google），送出前會再次提醒，建議先刪除不需要的欄位。
* AI 可能出錯，金額、人數等重要數字請以系統頁面為準。

### 3-3. 會議與社員大會（線上開會、投票、會議紀錄）
側邊欄「社務管理 → 會議與社員大會」。支援定期／臨時社員大會、幹部會議、法規監察委員會會議。

1. **召開會議**（幹部）：填寫日期、地點、線上會議連結、主席與紀錄、議程（報告事項、討論事項、選舉、臨時動議），每個議案可選表決門檻並連結法規修正案。
2. **開會通知**：輸入幾個關鍵字，按「✨ AI 產生開會通知」，修改後可儲存，或一鍵「發佈成官網公告」。按「公告會議」後社員才看得到。
3. **開會與簽到**：按「開始開會」時，系統依社員名冊自動算出應出席人數（具表決權的社員；也可手動輸入）。社員在後台按「我要簽到」；可設定**簽到碼**在現場公布，防止遠端代簽。主席也可以替現場的社員登記出席。沒有表決權的人簽到後列為列席，不計入法定人數。
4. **線上投票**：主席逐案「開放線上投票」，已簽到且有表決權的社員投同意／反對／棄權。投票為**無記名**：系統只記錄誰投過（防止重複投票），不記錄投給哪一方，投票結束前也不顯示票數。也可以改用「輸入現場票數」。
   * 表決門檻自動判定：一般決議（社員總額 1/3 出席、出席 1/2 同意，章程第十條第三款）、重大決議（2/3、2/3，第十條第四款）、罷免（1/2 出席、2/3 同意，第九條第四款）、委員會（1/2、1/2，可否同數不通過，第十二條第五款）。
   * 連結修正案的議案通過後，社長可按「帶入『法規查詢』登錄修正案通過」，自動帶入會議日期與票數。
5. **會議紀錄**：開會時在每個議案的「現場紀錄」打關鍵字即可。散會後按「✨ AI 產生會議紀錄」，AI 依議程、出席人數、票數與關鍵字寫成正式紀錄（票數一律照系統資料）。檢查修改後按「定稿」，所有社員都能閱讀、列印或另存 PDF；定稿後不能修改，社長可取消定稿。
* **免帳號簽到（學號＋姓名）**：社員大會預設開放。主席在會議頁按「複製連結」，把 `/meeting/…` 連結貼到群組；社員用手機開啟，輸入學號、姓名（須與社員名冊相符）與**現場簽到碼**就能簽到、投票，不需要後台帳號。
  * **簽到碼必備**：只在現場公布。主席沒設定的話，按「開始開會」時系統會自動產生 6 碼（不含 0/O、1/I 等易混淆字元）。有帳號的社員在後台簽到也要輸入。
  * **一台裝置一人**：簽到後綁定該瀏覽器；同一台裝置不能再替別人簽到，同一個學號也不能在其他裝置重複簽到（換手機請主席在簽到名單按 × 重設）。
  * **IP 只做紀錄**：簽到名單會顯示每個人的簽到方式與 IP 供主席查核，不會因 IP 擋人，學校 Wi-Fi 多人共用同一 IP 也沒問題。
  * 防猜學號：同一 IP 對同一場會議輸錯 30 次後需等 15 分鐘（簽到成功不計入）。
* **定期社員大會**：會議列表上方可一鍵建立本學期「期初／期末社員大會」，自動帶入預算／決算報告、選舉等常用議程。每週報告會提醒本學期是否已安排兩場定期大會。
* **社員帳號登入開關**：社長在「帳號與權限」可關閉「開放社員帳號登入」。關閉後社員角色的帳號無法登入（已登入者會被登出），幹部不受影響；社員改用會議連結簽到。
* 有後台帳號的社員，需在「帳號與權限」綁定社員資料才能在後台簽到與投票。
* 部署：新增了 `MEETING_STORE` Durable Object（`wrangler.toml` 的 migration `v4`），推送後 GitHub Actions 會自動建立。

### 3-4. 社團通訊與外部推播（Durable Object MessageStore）
後台與桌面版提供專屬「社團通訊 / 訊息中心」（`/api/messages/*`、`/api/announcements/*`），所有訊息資料由 Cloudflare Workers **`MESSAGE_STORE` Durable Object**（原生 SQLite 儲存架構，`wrangler.toml` migration `v5`）集中管理，支援多端同步、未讀狀態追蹤與安全防護：

1. **聊天室（Channels）**：
   * 支援「全體社員」、「幹部限定」及「指定成員」專屬群組。
   * 可設定「公告用頻道（僅幹部可發言）」，適合社務重要通知與課堂宣告。
   * 支援訊息作者編輯、刪除，社長具備全站頻道管理與封存權限。
2. **私人訊息（Direct Messages）**：
   * 任何登入帳號皆可與社團其他成員開啟一對一私密對話。
   * 具備已讀位置（`seq`）精確標記，未讀訊息即時統計。
3. **社團公告（Announcements）**：
   * 幹部可發布正式公告，支援置頂、全體／幹部限定發布。
   * 幹部可即時查看「已讀人數」與展開「已讀名單」，掌握通知觸及率。
4. **外部推播模組（選用模組，社長專屬設定）**：
   * 預設關閉。啟用後，當發布「全體社員公告」或「網站新文章」時，自動推播至外部社群平台：
     * **Webhook 整合**：支援 Discord 頻道 Webhook、Slack、Google Chat、Microsoft Teams 的 Incoming Webhook（最多可設定 5 組 Webhook 頻道）。
     * **LINE 官方帳號**：設定 Channel Access Token 即可透過 LINE Messaging API Broadcast 廣播推播至社團官方 LINE 好友。
   * **隱私隔離**：聊天室內容、私人訊息與「幹部限定公告」永遠不會外流至外部平台；Webhook 網址在查詢介面中皆自動遮蔽保護。
5. **跨端同步與桌面版整合**：
   * 網頁後台提供紅色未讀徽章、瀏覽器標題未讀提示 `(N)` 與即時 Toast 提醒。
   * 桌面版「社務管理系統」支援背景執行、Windows 系統匣氣泡推播通知與側邊功能樹未讀計數。
* **部署說明**：使用 `MESSAGE_STORE` Durable Object（`wrangler.toml` 的 migration `v5`），推送至 GitHub 後 GitHub Actions 自動部署套用 migration，無須手動設定。


### 4. 獨立網頁建立 (Custom Pages)
* 如果您需要為社團迎新、比賽報名或贊助招商建立專屬介紹頁，前往 **「頁面管理」** -> 「新增獨立網頁」。
* 填寫標題與路徑（例如 `join-us`；文章與頁面的路徑只能使用英文字母、數字、底線或連字號，最多 100 字），儲存後即可直接透過 `https://您的網站網址/page/join-us` 分享給所有人，無須修改任何一行程式碼！

## ⚠️ 錯誤自查與排除指南 (Troubleshooting)

為了協助您在運營時快速排解任何潛在問題，以下整理了常見的驗證檢查點：

1. **Q: 為什麼 GitHub Actions 顯示失敗 (紅叉)？**
   * **檢查原因**：最常見的原因是未設定 `CLOUDFLARE_KV_ID` 等機密變數。
   * **解決方式**：點進 GitHub Actions 的失敗 Log，若看到 `CLOUDFLARE_KV_ID secret is not set...`，請回到 GitHub Settings -> Secrets and variables -> Actions 補齊該金鑰即可。
2. **Q: 前台或後台讀取資料顯示 500 錯誤？**
   * **檢查原因**：KV 資料庫綁定遺失或名稱不符。
   * **解決方式**：請在 Cloudflare 後台的 Worker 設定確認 **KV Namespace Bindings** 中，`DRONE_DB` 變數名稱有正確指向您在第一步建立的 KV Namespace。
